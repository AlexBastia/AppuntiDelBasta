The NordicMart Lake

A live session against NordicMart's web-shop clickstream lake — raw, cleaned and curated zones, queried with schema-on-read, plus the data swamp it takes governance to avoid.

    About this demo

    What this is. A small SQL engine built for this page — a stand-in for a real lake query engine such as DuckDB or Spark SQL, which can run SQL directly against raw CSV, JSON or Parquet files with no load step. It supports SELECT, WHERE, GROUP BY, ORDER BY, LIMIT and the aggregates COUNT/SUM/AVG/MIN/MAX. Try queries like SELECT * FROM raw.events_2026_09_21 LIMIT 5 or SELECT event_type, COUNT(*) AS n FROM cleaned.events GROUP BY event_type.

    The data. A synthetic three-day slice of NordicMart's web-shop clickstream (393 raw events across three daily JSON partitions), deduplicated into 344 cleaned events, and rolled up into an 18-row churn-feature table — the same shape of table the "Why Machine Learning needs the lake" frame describes. One undocumented file sits outside all three zones with no catalog entry, on purpose.

    Runs offline. Everything here — data, engine and UI — is embedded in this one page. No server, no network call, no login. It runs the same way with the classroom wifi off.

    NordicMart is a fictional retailer used throughout this course. Data is synthetic.
