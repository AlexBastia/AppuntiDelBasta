[Java][Teoria] Disegna la <b>tassonomia</b> delle classi annidate in Java.	<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Nested classes<br>|-- Static nested class<br>`-- Inner class<br>&nbsp;&nbsp;&nbsp;&nbsp;|-- Member inner class<br>&nbsp;&nbsp;&nbsp;&nbsp;|-- Local class<br>&nbsp;&nbsp;&nbsp;&nbsp;`-- Anonymous class</code></div><br>&bull; <b>nested statica</b>: dichiarata con <code>static</code><br>&bull; <b>inner class</b>: NON statica<br>&bull; <b>local class</b>: inner dichiarata dentro un metodo/blocco<br>&bull; <b>anonymous class</b>: una classe locale <b>senza nome</b><br><br><b>Attenzione al vocabolario:</b> tutte le inner sono nested, ma <b>non</b> tutte le nested sono inner --- quelle <code>static</code> non lo sono.
[Java][Trabocchetto] Vero o falso: <i>tutte le nested class sono inner class</i>.	<b>FALSO.</b><br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>static class A { }   // nested, ma NON inner<br>class B { }          // nested E inner</code></div>Le <b>static nested class</b> non sono inner class, perche' non sono legate a un'istanza della classe esterna.<br><br>E' l'errore di vocabolario piu' comune sull'argomento.
[Java][Teoria] Quali sono i <b>vantaggi</b> di usare classi annidate?	&bull; maggiore <b>organizzazione</b> del codice<br>&bull; migliore <b>incapsulamento</b><br>&bull; <b>accesso diretto</b> ai membri della classe esterna<br>&bull; riduzione del numero di classi <b>visibili all'esterno</b><br>&bull; possibilita' di modellare componenti strettamente collegati<br><br>Si usano quando una classe ha senso <b>solo in relazione</b> a un'altra (es. <code>Motore</code> dentro <code>Automobile</code>).
[Java][Teoria] Cos'e' una <b>static nested class</b>, e a cosa puo' accedere?	Una classe dichiarata dentro un'altra con la keyword <code>static</code>.<br><br><b>Caratteristica principale:</b> NON e' associata a una specifica <b>istanza</b> della classe esterna.<br><br>Percio' puo' accedere <b>direttamente solo ai membri statici</b> dell'esterna.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Esterna {<br>&nbsp;&nbsp;&nbsp;&nbsp;private static int valoreStatico = 10;<br>&nbsp;&nbsp;&nbsp;&nbsp;private int valoreIstanza = 20;<br><br>&nbsp;&nbsp;&nbsp;&nbsp;static class Annidata {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;void mostra() {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;System.out.println(valoreStatico);      // OK<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;// System.out.println(valoreIstanza);   // ERRORE<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}</code></div>
[Java][Cosa fa?] <br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Esterna {<br>&nbsp;&nbsp;&nbsp;&nbsp;static class Annidata {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;void mostraMessaggio() {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;System.out.println("Sono una static nested class");<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}</code></div><br>Come si crea un oggetto di <code>Annidata</code>?	<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Esterna.Annidata oggetto = new Esterna.Annidata();<br>oggetto.mostraMessaggio();</code></div><br><b>NON serve</b> creare prima un oggetto di <code>Esterna</code>.<br><br>Il nome e' <b>qualificato dalla CLASSE</b> (<code>Esterna.Annidata</code>), non da un'istanza.
[Java][Trabocchetto] Una static nested class puo' accedere ai membri <b>private</b> della classe esterna?	<b>SI'</b> --- purche' disponga di un'<b>istanza</b>, quando il membro non e' statico.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Conto {<br>&nbsp;&nbsp;&nbsp;&nbsp;private double saldo = 1000;          // PRIVATO<br><br>&nbsp;&nbsp;&nbsp;&nbsp;static class Controllore {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;void controlla(Conto conto) {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;System.out.println(conto.saldo);   // OK!<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}</code></div><b>Il punto:</b> l'incapsulamento vale verso il <b>mondo esterno</b>, non fra classe esterna e classe annidata --- che sono considerate parte della stessa unita' di codice.
[Java][Scrivi] <b>Scrivi</b> il pattern <b>Builder</b>, l'uso tipico di una static nested class.	<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Utente {<br>&nbsp;&nbsp;&nbsp;&nbsp;private final String nome;<br>&nbsp;&nbsp;&nbsp;&nbsp;private final int eta;<br><br>&nbsp;&nbsp;&nbsp;&nbsp;private Utente(Builder builder) {       // costruttore PRIVATO<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;this.nome = builder.nome;<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;this.eta  = builder.eta;<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br><br>&nbsp;&nbsp;&nbsp;&nbsp;public static class Builder {           // STATIC: non serve un Utente<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;private String nome;<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;private int eta;<br><br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;public Builder nome(String nome) {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;this.nome = nome;<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;return this;                    // fluent interface<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;public Builder eta(int eta) {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;this.eta = eta;<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;return this;<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;public Utente build() {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;return new Utente(this);<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}</code></div>Uso:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Utente utente = new Utente.Builder()<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;.nome("Luca")<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;.eta(30)<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;.build();</code></div><b>Perche' static:</b> il Builder costruisce un <code>Utente</code>, quindi non puo' dipendere da un <code>Utente</code> gia' esistente.
[Java][Teoria] Cos'e' una <b>inner class</b>, e in cosa differisce da una static nested?	Una classe annidata <b>NON</b> dichiarata <code>static</code>.<br><br><b>Differenza fondamentale:</b> ogni oggetto della inner class e' collegato a uno <b>specifico oggetto</b> della classe esterna.<br><br>E' come se ogni oggetto interno contenesse implicitamente un <b>riferimento</b> all'oggetto esterno che lo ha creato:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Documento<br>&nbsp;&nbsp;&nbsp;&nbsp;`-- riferimento implicito a Persona</code></div>
[Java][Cosa fa?][Trabocchetto] <br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Esterna {<br>&nbsp;&nbsp;&nbsp;&nbsp;class Interna { void saluta() { } }<br>}<br><br>// nel main:<br>Esterna.Interna a = new Esterna.Interna();        // (1)<br><br>Esterna esterna = new Esterna();<br>Esterna.Interna b = esterna.new Interna();        // (2)</code></div><br>Quale delle due righe compila?	Solo la <b>(2)</b>.<br><br>La riga (1) e' un <b>errore</b>. Messaggio reale:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>error: non-static variable this cannot be&lt;br&gt;       referenced from a static context</code></div>Una inner class <b>richiede un'istanza esterna</b> a cui agganciarsi.<br><br>La sintassi corretta e' particolare e va ricordata:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>esterna.new Interna()</code></div>cioe' <code>new</code> preceduto dall'<b>oggetto</b> esterno (non dalla classe).
[Java][Teoria] A cosa puo' accedere una <b>inner class</b> della classe esterna?	A <b>tutto</b>:<br>&bull; campi di <b>istanza</b><br>&bull; metodi di <b>istanza</b><br>&bull; membri <b>statici</b><br>&bull; membri <b>privati</b><br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Contatore {<br>&nbsp;&nbsp;&nbsp;&nbsp;private int valore = 0;               // privato, di istanza<br><br>&nbsp;&nbsp;&nbsp;&nbsp;public class Incrementatore {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;public void incrementa() { valore++; }     // accesso diretto!<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;public void mostra() { System.out.println(valore); }<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}</code></div>Nessun bisogno di passare nulla: il riferimento all'esterno e' <b>implicito</b>.
[Java][Cosa fa?] <br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Contatore c1 = new Contatore();<br>Contatore c2 = new Contatore();<br><br>Contatore.Incrementatore i1 = c1.new Incrementatore();<br>Contatore.Incrementatore i2 = c2.new Incrementatore();<br><br>i1.incrementa();<br>i1.incrementa();<br>i2.incrementa();</code></div><br>Su quali stati lavorano <code>i1</code> e <code>i2</code>?	<b>Su stati DIVERSI.</b><br><br>&bull; <code>i1</code> modifica il valore di <code>c1</code> &rarr; 2<br>&bull; <code>i2</code> modifica il valore di <code>c2</code> &rarr; 1<br><br>Ogni oggetto inner e' legato all'<b>istanza esterna che lo ha creato</b>: due oggetti esterni danno due "mondi" separati.<br><br><i>(verificato eseguendo un caso analogo: la stessa strategia inner dava 20 e poi 1 dopo aver cambiato il campo dell'esterno)</i>
[Java][Cosa fa?][Esame] <br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Esterna {<br>&nbsp;&nbsp;&nbsp;&nbsp;private int valore = 10;<br><br>&nbsp;&nbsp;&nbsp;&nbsp;class Interna {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;private int valore = 20;<br><br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;void mostra() {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;int valore = 30;<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;System.out.println(valore);<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;System.out.println(this.valore);<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;System.out.println(Esterna.this.valore);<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}</code></div><br>Cosa stampa?	<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>30<br>20<br>10</code></div><br>&bull; <code>valore</code> &rarr; la <b>variabile locale</b> (30)<br>&bull; <code>this.valore</code> &rarr; il campo dell'oggetto <b>interno</b> (20)<br>&bull; <code>Esterna.this.valore</code> &rarr; il campo dell'oggetto <b>esterno</b> associato (10)<br><br><b><code>Esterna.this</code> e' la sintassi chiave delle inner class:</b> e' l'unico modo di nominare esplicitamente l'enclosing instance.<br><br>Il fenomeno si chiama <b>shadowing</b>: un nome piu' interno nasconde quello piu' esterno.
[Java][Trabocchetto] Perche' una <b>inner class</b> puo' causare un <b>memory leak</b>?	Perche' conserva un <b>riferimento implicito</b> all'oggetto esterno, che quindi non puo' essere liberato dal garbage collector.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Contenitore {<br>&nbsp;&nbsp;&nbsp;&nbsp;private byte[] dati = new byte[10_000_000];   // 10 MB<br><br>&nbsp;&nbsp;&nbsp;&nbsp;public class Elemento {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;void mostra() { System.out.println(dati.length); }<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}<br><br>Contenitore contenitore = new Contenitore();<br>Contenitore.Elemento elemento = contenitore.new Elemento();<br>contenitore = null;        // &lt;- l'oggetto NON viene liberato!</code></div>L'oggetto esterno resta <b>raggiungibile attraverso</b> <code>elemento</code>, quindi i 10 MB restano allocati.<br><br><b>Regola pratica:</b> se la classe annidata non ha bisogno dell'istanza esterna, dichiarala <b><code>static</code></b>.
[Java][Teoria] Quali <b>modificatori di accesso</b> puo' avere una classe annidata? E una classe top-level?	<b>Classe annidata (membro):</b> tutti e quattro<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Esempio {<br>&nbsp;&nbsp;&nbsp;&nbsp;public class Pubblica { }<br>&nbsp;&nbsp;&nbsp;&nbsp;protected class Protetta { }<br>&nbsp;&nbsp;&nbsp;&nbsp;private class Privata { }<br>&nbsp;&nbsp;&nbsp;&nbsp;class PackagePrivate { }<br>}</code></div><b>Classe top-level:</b> solo <code>public</code> oppure package-private (nessun modificatore).<br><br><b>Non puo'</b> essere direttamente <code>private</code> ne' <code>protected</code>: non avrebbe senso, perche' non c'e' nessuna classe che la racchiuda rispetto a cui essere privata.
[Java][Teoria] Cos'e' una <b>local class</b> e qual e' il suo ambito di visibilita'?	Una classe dichiarata dentro un <b>metodo</b>, un <b>costruttore</b> o un <b>blocco</b>.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public void esegui() {<br>&nbsp;&nbsp;&nbsp;&nbsp;class ClasseLocale {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;void saluta() { System.out.println("Sono locale"); }<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;ClasseLocale oggetto = new ClasseLocale();<br>&nbsp;&nbsp;&nbsp;&nbsp;oggetto.saluta();<br>}</code></div><b>Visibilita':</b> solo <b>dopo la sua dichiarazione</b> e <b>dentro il blocco</b> che la contiene.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public void esempio() {<br>&nbsp;&nbsp;&nbsp;&nbsp;// Locale a = new Locale();   // ERRORE: non ancora dichiarata<br>&nbsp;&nbsp;&nbsp;&nbsp;class Locale { }<br>&nbsp;&nbsp;&nbsp;&nbsp;Locale b = new Locale();      // OK<br>}</code></div>In un altro metodo il nome <b>non esiste</b>.
[Java][Teoria][Esame] Una local class puo' accedere alle <b>variabili locali</b> del metodo? A quale condizione?	<b>SI'</b>, ma solo se sono <b><code>final</code></b> oppure <b>effectively final</b>.<br><br>Una variabile e' <i>effectively final</i> quando viene assegnata <b>una sola volta</b> e non viene mai piu' modificata.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public void mostra() {<br>&nbsp;&nbsp;&nbsp;&nbsp;String messaggio = "Ciao";        // effectively final: OK<br>&nbsp;&nbsp;&nbsp;&nbsp;class Stampante {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;void stampa() { System.out.println(messaggio); }<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;new Stampante().stampa();<br>}</code></div>Questo invece <b>non compila</b>:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public void mostra() {<br>&nbsp;&nbsp;&nbsp;&nbsp;String messaggio = "Ciao";<br>&nbsp;&nbsp;&nbsp;&nbsp;messaggio = "Buongiorno";         // RIASSEGNATA -&gt; non piu' eff. final<br>&nbsp;&nbsp;&nbsp;&nbsp;class Stampante {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;void stampa() { System.out.println(messaggio); }   // ERRORE<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}</code></div>Messaggio reale del compilatore:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>error: local variables referenced from an inner&lt;br&gt;       class must be final or effectively final</code></div>
[Java][Teoria][Esame] <b>Perche'</b> Java richiede che le variabili catturate siano <code>final</code> o effectively final?	Perche' le variabili locali vivono nello <b>stack</b> del metodo e <b>smettono di esistere</b> quando il metodo termina --- ma l'oggetto della classe locale <b>puo' sopravvivergli</b>.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public Runnable creaOperazione() {<br>&nbsp;&nbsp;&nbsp;&nbsp;int valore = 10;<br>&nbsp;&nbsp;&nbsp;&nbsp;class Operazione implements Runnable {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;public void run() { System.out.println(valore); }<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;return new Operazione();      // il metodo finisce, l'oggetto resta<br>}</code></div>Quindi Java <b>non usa la variabile</b>: ne memorizza una <b>COPIA</b> dentro l'oggetto.<br><br>Se la variabile potesse cambiare, si creerebbe ambiguita' fra il <b>valore originale</b> e il <b>valore copiato</b>: la regola elimina l'incoerenza alla radice.
[Java][Scrivi] <b>Scrivi</b> una local class dichiarata dentro un <b>costruttore</b>, usata per validare un parametro.	<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>public class Prodotto {<br><br>&nbsp;&nbsp;&nbsp;&nbsp;public Prodotto(String nome) {<br><br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;class Validatore {                     // esiste solo qui<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;boolean valido() {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;return nome != null &amp;&amp; !nome.isBlank();<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br><br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;Validatore validatore = new Validatore();<br><br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;if (!validatore.valido()) {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;throw new IllegalArgumentException("Nome non valido");<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>}</code></div><b>Perche' local:</b> il validatore serve <b>solo durante la costruzione</b>; non ha senso esporlo come tipo nel resto della classe. Nota che cattura il parametro <code>nome</code> (effectively final).<br><br>Una local class si puo' dichiarare anche in un blocco <code>if</code>, <code>for</code>, <code>while</code>, <code>try</code>.
[Java][Teoria] Cos'e' una <b>anonymous class</b>?	Una classe <b>senza nome</b>, dichiarata e <b>istanziata nello stesso momento</b>. E' considerata una forma particolare di local class.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Saluto saluto = new Saluto() {<br>&nbsp;&nbsp;&nbsp;&nbsp;@Override<br>&nbsp;&nbsp;&nbsp;&nbsp;public void saluta() { System.out.println("Ciao!"); }<br>};</code></div><b>Attenzione alla semantica:</b> la sintassi <code>new Saluto() {...}</code> <b>non</b> crea un oggetto dell'interfaccia <code>Saluto</code>: crea un oggetto di una <b>classe anonima che la implementa</b>.<br><br>Puo' anche <b>estendere una classe</b>, non solo implementare un'interfaccia.
[Java][Trabocchetto] Una classe anonima puo' avere un <b>costruttore</b>?	<b>NO</b> --- perche' non possiede un nome, e il costruttore deve avere lo stesso nome della classe.<br><br>Puo' pero' usare un <b>blocco di inizializzazione</b>:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Animale animale = new Animale() {<br>&nbsp;&nbsp;&nbsp;&nbsp;{<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;System.out.println("Inizializzazione della classe anonima");<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>&nbsp;&nbsp;&nbsp;&nbsp;@Override<br>&nbsp;&nbsp;&nbsp;&nbsp;public void verso() { System.out.println("Miao"); }<br>};</code></div>
[Java][Trabocchetto] <br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Animale animale = new Animale() {<br>&nbsp;&nbsp;&nbsp;&nbsp;private int energia = 100;<br><br>&nbsp;&nbsp;&nbsp;&nbsp;void dormi() { energia += 10; }        // metodo NUOVO<br><br>&nbsp;&nbsp;&nbsp;&nbsp;@Override<br>&nbsp;&nbsp;&nbsp;&nbsp;public void verso() { System.out.println("Energia: " + energia); }<br>};<br><br>animale.dormi();     // ???</code></div><br>L'ultima riga compila?	<b>NO.</b><br><br>Il metodo <code>dormi()</code> appartiene davvero alla classe anonima, ma il <b>tipo statico</b> della variabile e' <code>Animale</code>, che non lo dichiara.<br><br>Una classe anonima <b>puo'</b> dichiarare nuovi campi e metodi, ma sono <b>irraggiungibili dall'esterno</b>: non esiste un nome di tipo con cui riferirsi ad essa.<br><br>E' un limite intrinseco dell'anonimato --- ed e' il motivo per cui, se servono membri aggiuntivi accessibili, si usa una local class con nome.
[Java][Teoria][Esame] Qual e' la <b>differenza nell'uso di <code>this</code></b> fra una classe anonima e una lambda?	<b>Classe anonima:</b> <code>this</code> indica l'<b>oggetto anonimo</b>.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Runnable r = new Runnable() {<br>&nbsp;&nbsp;&nbsp;&nbsp;public void run() { System.out.println(this); }   // l'oggetto anonimo<br>};</code></div><b>Lambda:</b> <code>this</code> indica l'oggetto della <b>classe che contiene</b> la lambda.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Runnable r = () -&gt; System.out.println(this);   // l'oggetto di Esempio</code></div><b>Le lambda NON introducono un nuovo contesto per <code>this</code>.</b><br><br>E' la ragione principale per cui una lambda <b>non</b> e' sempre sostituibile a una classe anonima, anche quando l'interfaccia e' funzionale.
[Java][Teoria] Quando si puo' sostituire una anonymous class con una <b>lambda</b>?	Quando l'interfaccia ha <b>un solo metodo astratto</b> (interfaccia funzionale).<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>@FunctionalInterface<br>public interface Operazione { int esegui(int a, int b); }<br><br>// anonymous class<br>Operazione somma = new Operazione() {<br>&nbsp;&nbsp;&nbsp;&nbsp;@Override<br>&nbsp;&nbsp;&nbsp;&nbsp;public int esegui(int a, int b) { return a + b; }<br>};<br><br>// lambda: equivalente e piu' breve<br>Operazione somma = (a, b) -&gt; a + b;</code></div><b>Usa la lambda quando:</b> il tipo e' un'interfaccia funzionale, non serve uno stato complesso, e <b>non serve un nuovo significato di <code>this</code></b>.

[C++][Teoria][Esame] In C++, una <b>nested class</b> richiede un oggetto della classe esterna? Conserva <code>this</code> dell'esterna?	<b>No</b> a entrambe.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Esterna::Annidata oggetto;      // basta questo</code></div>In C++ una classe annidata e' <b>sempre</b> l'equivalente di una <code>static</code> nested class di Java: e' solo una questione di <b>scope e naming</b>.<br><br>Per avere un legame con l'oggetto esterno bisogna <b>scriverlo a mano</b>, memorizzando un <code>Esterna&amp;amp;</code> o un <code>Esterna*</code>.<br><br><b>In C++ NON esiste l'inner class di Java.</b>

[C++][Teoria][Esame] Una <b>local class</b> C++ puo' usare le variabili locali della funzione che la contiene?	<b>NO.</b> Errore reale del compilatore:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>error: use of local variable with automatic storage&lt;br&gt;       from containing function</code></div>Puo' usare <b>solo</b>: variabili <code>static</code>, globali, <code>enum</code> e tipi.<br><br><b>Il motivo:</b> una local class e' un <i>tipo</i>, e i suoi metodi sono funzioni ordinarie; non esiste alcun meccanismo che copi le variabili locali dentro l'oggetto.<br><br>In Java quel meccanismo esiste (cattura per valore delle <i>effectively final</i>). In C++ e' arrivato nel 2011 e si chiama <b>lambda</b>.<br><br><b>Soluzione:</b> passare i dati <b>esplicitamente</b>, es. nel costruttore.
[C++][Trabocchetto] Una local class C++ puo' avere <b>membri dati static</b>?	<b>NO.</b> Errore reale:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>error: local class 'class g()::L' shall not have&lt;br&gt;       static data member 'int g()::L::m'</code></div>Un membro dati static richiederebbe una definizione a livello di <b>namespace</b>, che per una classe locale non e' esprimibile.<br><br><b>Puo' invece</b> avere: metodi static, tipi annidati e costanti <code>static const</code> integrali inizializzate in linea.
[C++][Teoria] Cos'e' davvero una <b>lambda</b> in C++?	Il compilatore genera un <b>tipo senza nome</b> (<i>closure type</i>), <b>locale</b> allo scope in cui la lambda appare, con:<br>&bull; un <code>operator()</code><br>&bull; un membro per ogni variabile catturata<br><br>E' quindi letteralmente una <b>classe locale anonima con cattura</b>: risolve il limite della local class e fornisce l'equivalente della classe anonima di Java.<br><br><b>Verificato (sizeof):</b><br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>lambda che cattura un int  =  4 byte   (solo la cattura, NESSUN vptr)<br>lambda senza cattura       =  1 byte   (oggetto vuoto)<br>classe con metodo virtuale =  8 byte   (il vptr)<br>std::function&lt;int(int,int)&gt; = 32 byte  (type erasure)</code></div>
[C++][Teoria][Esame] Cosa significano le quattro forme di <b>cattura</b> <code>[x]</code>, <code>[&amp;x]</code>, <code>[=]</code>, <code>[&amp;]</code>?	&bull; <code>[x]</code> &rarr; cattura <b>x per valore</b> (una copia)<br>&bull; <code>[&amp;x]</code> &rarr; cattura <b>x per riferimento</b><br>&bull; <code>[=]</code> &rarr; cattura <b>tutto</b> per valore (automaticamente, solo le variabili usate)<br>&bull; <code>[&amp;]</code> &rarr; cattura <b>tutto</b> per riferimento<br><br>Si possono <b>mischiare</b>:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>int a = 10, b = 20;<br>auto operazione = [a, &amp;b]() { b += a; };   // a copiato, b per riferimento</code></div><b>Consiglio:</b> <code>[=]</code> e <code>[&amp;]</code> sono comode ma rendono meno chiaro quali variabili si usino davvero. Meglio la cattura <b>esplicita</b>.
[C++][Cosa fa?] <br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>int numero = 10;<br><br>auto mostra = [numero]() { std::cout &lt;&lt; numero &lt;&lt; '\n'; };<br><br>numero = 20;<br>mostra();</code></div><br>Cosa stampa?	Stampa <b>10</b>.<br><br>La lambda ha catturato il <b>valore al momento della sua creazione</b>: conserva una <b>copia</b>, non un collegamento.<br><br>Con la cattura per riferimento invece:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>int numero = 10;<br>auto incrementa = [&amp;numero]() { ++numero; };<br>incrementa();<br>std::cout &lt;&lt; numero;      // stampa 11</code></div>qui la lambda lavora sulla <b>variabile originale</b>.
[C++][Trabocchetto][Esame] A cosa serve <code>mutable</code> in una lambda?	Per impostazione predefinita l'<code>operator()</code> generato e' <b>const</b>: una variabile catturata <b>per valore</b> non puo' essere modificata.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>auto operazione = [numero]() {<br>&nbsp;&nbsp;&nbsp;&nbsp;// ++numero;      // ERRORE: operator() e' const<br>};</code></div>Con <code>mutable</code> si puo':<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>int numero = 10;<br>auto operazione = [numero]() mutable {<br>&nbsp;&nbsp;&nbsp;&nbsp;++numero;<br>&nbsp;&nbsp;&nbsp;&nbsp;std::cout &lt;&lt; numero &lt;&lt; '\n';      // stampa 11<br>};<br>operazione();<br>std::cout &lt;&lt; numero &lt;&lt; '\n';          // stampa 10 !</code></div><b>Punto chiave:</b> viene modificata <b>solo la copia interna</b> alla lambda. La variabile originale resta <b>invariata</b>.
[C++][Teoria] Cos'e' una <b>init capture</b> (C++14)?	Una cattura che <b>inizializza direttamente</b> una variabile membro della closure:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>auto operazione = [valore = 42]() {<br>&nbsp;&nbsp;&nbsp;&nbsp;std::cout &lt;&lt; valore &lt;&lt; '\n';<br>};</code></div>Serve soprattutto per <b>spostare</b> un oggetto dentro la lambda (cosa impossibile con le catture classiche):<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>auto puntatore = std::make_unique&lt;int&gt;(42);<br><br>auto operazione = [p = std::move(puntatore)]() {<br>&nbsp;&nbsp;&nbsp;&nbsp;std::cout &lt;&lt; *p &lt;&lt; '\n';<br>};</code></div>
[C++][Teoria] Cosa cattura <code>[this]</code> in una lambda dentro un metodo? E <code>[*this]</code>?	<code>[this]</code> cattura il <b>puntatore</b> all'oggetto: la lambda accede ai membri dell'oggetto <b>originale</b>.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>class Contatore {<br>&nbsp;&nbsp;&nbsp;&nbsp;int valore = 10;<br>public:<br>&nbsp;&nbsp;&nbsp;&nbsp;void mostra() {<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;auto operazione = [this]() { std::cout &lt;&lt; valore &lt;&lt; '\n'; };<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;operazione();<br>&nbsp;&nbsp;&nbsp;&nbsp;}<br>};</code></div><code>[*this]</code> (da C++17) cattura una <b>copia dell'intero oggetto</b>.<br><br><b>Differenza cruciale:</b> con <code>[this]</code>, se l'oggetto muore prima della lambda, si ha un puntatore <b>pendente</b>. Con <code>[*this]</code> la lambda e' autonoma.
[C++][Trabocchetto] Qual e' il <b>rischio principale</b> della cattura per riferimento?	La lambda puo' <b>sopravvivere</b> alle variabili catturate, producendo <b>riferimenti pendenti</b> (dangling) e <b>undefined behavior</b>.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>std::function&lt;void()&gt; crea() {<br>&nbsp;&nbsp;&nbsp;&nbsp;int locale = 42;<br>&nbsp;&nbsp;&nbsp;&nbsp;return [&amp;locale]() {          // PERICOLO<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;std::cout &lt;&lt; locale;      // 'locale' non esiste piu'!<br>&nbsp;&nbsp;&nbsp;&nbsp;};<br>}</code></div>Quando la funzione ritorna, <code>locale</code> e' distrutta: la lambda punta a memoria non piu' valida.<br><br><b>Regola:</b> se la lambda puo' vivere piu' a lungo dello scope corrente (la si restituisce, la si memorizza, la si passa a un thread), cattura <b>per valore</b>.
[C++][Trabocchetto] Elenca gli <b>errori comuni</b> con nested/local/lambda in C++.	1. credere che esista un <b>riferimento implicito</b> all'oggetto esterno (non esiste: va scritto a mano)<br>2. usare <code>.</code> invece di <code>::</code> per il <b>tipo</b>: si scrive <code>Esterna::Annidata</code>, non <code>Esterna.Annidata</code><br>3. restituire una lambda che cattura <b>per riferimento</b> variabili locali (dangling)<br>4. conservare un riferimento a un oggetto esterno <b>gia' distrutto</b><br>5. credere che una <b>classe locale catturi</b> le variabili (non lo fa: solo le lambda)<br>6. usare cattura per riferimento senza controllare la <b>durata</b><br>7. usare <code>std::function</code> <b>sempre</b>: introduce type erasure e un costo (32 byte + possibile allocazione) spesso inutile --- se il tipo e' noto, <code>auto</code> basta
[Python][Teoria] Cos'e', tecnicamente, una <b>classe annidata</b> in Python?	Semplicemente un <b>attributo</b> della classe esterna.<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>class Esterna:<br>&nbsp;&nbsp;&nbsp;&nbsp;class Annidata:<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;def saluta(self):<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;print("Sono una classe annidata")<br><br>oggetto = Esterna.Annidata()</code></div>E' concettualmente identico a scrivere:<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>class Annidata:<br>&nbsp;&nbsp;&nbsp;&nbsp;pass<br><br>class Esterna:<br>&nbsp;&nbsp;&nbsp;&nbsp;pass<br><br>Esterna.Annidata = Annidata</code></div>Il nome completo e' <code>Esterna.Annidata</code> --- e' quindi puro <b>namespacing</b>, come le nested del C++.
[Python][Cosa fa?][Esame] <br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>class Esterna:<br>&nbsp;&nbsp;&nbsp;&nbsp;def __init__(self):<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;self.valore = 10<br><br>&nbsp;&nbsp;&nbsp;&nbsp;class Annidata:<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;def mostra(self):<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;print(self.valore)<br><br>Esterna.Annidata().mostra()</code></div><br>Stampa 10?	<b>NO</b> --- solleva <code>AttributeError</code>.<br><br>Dentro <code>Annidata</code>, <code>self</code> rappresenta un oggetto <b>Annidata</b>, non un oggetto <b>Esterna</b>.<br><br><b>In Python NON esistono le inner class automatiche di Java:</b> una classe annidata <b>non</b> conserva alcun riferimento all'oggetto esterno.<br><br><i>Verificato anche con un nome di classe: usando un attributo di classe non qualificato si ottiene</i> <code>NameError: name '...' is not defined</code><i>, perche' il corpo di una classe non crea uno scope annidato per la ricerca dei nomi.</i>

[Python][Teoria] Qual e' l'equivalente Python di una <b>classe anonima</b>?	Non esiste un costrutto dedicato. Ci sono due strade:<br><br><b>1. Una lambda</b> (per un solo comportamento):<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>operazione = lambda a, b: a + b</code></div><b>2. La funzione <code>type()</code></b>, che crea una classe dinamicamente ed e' l'unica cosa davvero "anonima":<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>Anonima = type(<br>&nbsp;&nbsp;&nbsp;&nbsp;"",                      # nome VUOTO<br>&nbsp;&nbsp;&nbsp;&nbsp;(BaseClass,),            # tuple delle basi<br>&nbsp;&nbsp;&nbsp;&nbsp;{                        # dizionario dei membri<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;"applica": lambda self, a, b: a + b,<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;"simbolo": lambda self: "+",<br>&nbsp;&nbsp;&nbsp;&nbsp;},<br>)<br>oggetto = Anonima()</code></div><b>Verificato:</b> <code>type(oggetto).__name__</code> e' la stringa <b>vuota</b>, e <code>isinstance(oggetto, BaseClass)</code> e' <code>True</code> --- e' una sottoclasse a tutti gli effetti, senza nome.<br><br><i>Nota: abusare di <code>type()</code> rende il codice illeggibile. Va usata solo quando serve davvero generare classi a runtime.</i>
[Python][Cosa fa?][Trabocchetto] <br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>funzioni = []<br>for i in range(3):<br>&nbsp;&nbsp;&nbsp;&nbsp;funzioni.append(lambda: i)<br><br>print([f() for f in funzioni])</code></div><br>Cosa stampa?	Stampa <b>[2, 2, 2]</b>, non <code>[0, 1, 2]</code>.<br><br>E' il problema del <b>late binding</b>: la lambda non cattura il <b>valore</b> di <code>i</code>, ma la <b>variabile</b>. Quando le lambda vengono chiamate, il ciclo e' finito e <code>i</code> vale 2.<br><br><b>Soluzione:</b> forzare la cattura del valore con un argomento di default (valutato alla <b>definizione</b>):<br><div style="text-align:left; display:inline-block; margin:6px 0;"><code>for i in range(3):<br>&nbsp;&nbsp;&nbsp;&nbsp;funzioni.append(lambda i=i: i)      # -&gt; [0, 1, 2]</code></div><b>Confronto:</b> in C++ e' la differenza fra <code>[&amp;i]</code> (late binding, come Python) e <code>[i]</code> (cattura per valore). In Java il problema <b>non esiste</b>, perche' la variabile catturata deve essere <i>effectively final</i>.
