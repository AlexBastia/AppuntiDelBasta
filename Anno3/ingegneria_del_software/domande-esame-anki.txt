[Pattern - esame aperto] Come si descrive la struttura del Factory Method in un linguaggio a scelta (es. Java)?	Una classe astratta/interfaccia <code>Creator</code> dichiara un metodo <code>factoryMethod()</code> che restituisce un <code>Product</code> astratto; le sottoclassi <code>ConcreteCreator</code> implementano <code>factoryMethod()</code> restituendo istanze di un <code>ConcreteProduct</code> specifico. Es.: <code>abstract class Creator { abstract Product factoryMethod(); }</code>. La scelta della classe concreta da istanziare è demandata alla sottoclasse, disaccoppiando il client dalle classi concrete dei prodotti.

[Pattern - esame aperto] Come si descrive la struttura del Prototype in Java?	Un'interfaccia (tipicamente <code>Cloneable</code>) dichiara un metodo di clonazione; le classi concrete implementano <code>clone()</code> restituendo una copia di se stesse:<br><code>class ConcretePrototype implements Cloneable {<br>&nbsp;&nbsp;public ConcretePrototype clone() {<br>&nbsp;&nbsp;&nbsp;&nbsp;return (ConcretePrototype) super.clone();<br>&nbsp;&nbsp;}<br>}</code><br>Il client crea nuovi oggetti chiamando <code>clone()</code> su un'istanza prototipica, invece di usare <code>new</code> e conoscere la classe concreta.

[Pattern - esame aperto] Come si descrive la struttura del Singleton in Python?	Si realizza tipicamente intercettando <code>__new__</code>:<br><code>class Singleton:<br>&nbsp;&nbsp;_instance = None<br>&nbsp;&nbsp;def __new__(cls):<br>&nbsp;&nbsp;&nbsp;&nbsp;if cls._instance is None:<br>&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;&nbsp;cls._instance = super().__new__(cls)<br>&nbsp;&nbsp;&nbsp;&nbsp;return cls._instance</code><br>oppure con una metaclasse Singleton generalizzata, riusabile su più classi. A differenza di Java/C++ (costruttore reso privato), in Python si intercetta la creazione dell'oggetto tramite <code>__new__</code>, perché il costruttore non può essere reso "privato" in senso stretto.

[Pattern - esame aperto] Scrivi il codice minimo che implementa le caratteristiche essenziali del Singleton (istanza unica, accesso globale controllato).	Esempio in Java:<br><code>public class Singleton {<br>&nbsp;&nbsp;private static Singleton instance;<br>&nbsp;&nbsp;private Singleton() {}<br>&nbsp;&nbsp;public static Singleton getInstance() {<br>&nbsp;&nbsp;&nbsp;&nbsp;if (instance == null) instance = new Singleton();<br>&nbsp;&nbsp;&nbsp;&nbsp;return instance;<br>&nbsp;&nbsp;}<br>}</code><br>Caratteristiche chiave: costruttore privato (impedisce <code>new</code> dall'esterno), campo statico che conserva l'unica istanza, metodo statico di accesso che la crea "lazy" (alla prima richiesta) e la restituisce sempre in seguito.

[Pattern - esame aperto] Come si descrive la struttura del design pattern del "clone" (Prototype)?	È lo stesso pattern Prototype: un'interfaccia comune dichiara un metodo <code>clone()</code>; ogni <code>ConcretePrototype</code> lo implementa restituendo una copia di se stesso (spesso una shallow copy tramite costrutti nativi del linguaggio, es. <code>super.clone()</code> in Java o <code>copy.deepcopy()</code>/<code>copy.copy()</code> in Python). Il <code>Client</code> usa <code>clone()</code> per creare nuovi oggetti senza dipendere dalla loro classe concreta né dal loro costruttore.

[Pattern - esame aperto] Qual è la differenza tra overloading e overriding?	<b>Overloading</b>: più metodi con lo stesso nome ma signature diversa (nella stessa classe, senza bisogno di una gerarchia); la scelta di quale invocare è risolta staticamente a compile-time in base ai tipi degli argomenti.<br><b>Overriding</b>: un metodo di una sottoclasse ridefinisce (stessa signature) un metodo virtual/non-final della superclasse; la scelta di quale versione eseguire è risolta dinamicamente a runtime in base alla classe reale dell'oggetto (late binding).
